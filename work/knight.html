Knight

An Unreal Engine 5 action RPG built on the Gameplay Ability System. GAS was the significant gap in four years of UE5 work, because the projects I shipped did not use it. This is me closing that gap: built alongside a structured course, but read against the engine source rather than followed step by step.

Type
Personal project
Engine
Unreal Engine 5, C++
Status
In progress, started Aug 2026
Source
github.com/mln-grg/Knight

Structure

The project follows the layered structure Epic uses in Lyra, scaled down. KnightBaseCharacter holds what any pawn needs; KnightHeroCharacter adds the player. The ability system component, combat component and input component hang off the pawn rather than accumulating on the character class.

Data-driven start-up

Abilities are not hardcoded into the character. DataAsset_HeroStartUpData declares which abilities a pawn is granted, and the ability system component applies them when the pawn is possessed. Adding an ability to the hero is a data change, not a code change.

Tag-driven input

DataAsset_InputConfig maps gameplay tags — InputTag.Move, InputTag.Look, InputTag.EquipAxe — to input actions, and KnightInputComponent binds them by tag. Input routing lives in data instead of a switch statement in the controller.

Component composition

UPawnExtensionComponentBase is a shared base for every component hung off a pawn. It carries no logic, only typed accessors with compile-time checks, so subclasses reach their owner without repeating casts. Combat splits into PawnCombatComponent for shared behaviour and HeroCombatComponent for player-specific behaviour.

Animation follows the same idea: KnightBaseAnimInstance and KnightCharacterAnimInstance hold shared state, and KnightHeroLinkedAnimLayer lets weapon-specific animation be swapped in as a linked layer rather than branching inside one large graph.

Where it actually is

Implemented:

  • Ability system component, attribute set scaffolding, gameplay ability base classes
  • Data-driven ability granting on possession
  • Tag-based input configuration and binding
  • Character hierarchy, combat component split, weapon base and hero weapon
  • Animation instance hierarchy with linked anim layers
  • Axe equip and unequip

Not implemented:

  • Attributes are declared but not populated, so there is no health, damage or ability cost yet
  • No enemies, no damage resolution, no death handling
  • One weapon, and no UI
