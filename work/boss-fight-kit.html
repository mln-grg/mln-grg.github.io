BossFightKit

A 2D combat prototype in Unity 6.5 URP, built as an exercise in making boss fights a designer can author and tune without touching code. Three fights are implemented, all rebuilt from Hollow Knight encounters: Absolute Radiance, the Mantis Lords and the Heart. There are no art or audio files in the repository.

Type
Personal project
Engine
Unity 6.5, URP, C#
Fights
3 implemented
Status
Sandbox, not a shipped game

The idea

A boss fight is mostly data. Which attacks exist, what order they come in, how long the telegraph lasts, when the next phase starts, where the arena walls are. Encoding that in code means every balance change is a recompile and only a programmer can make one.

So none of it lives in code here. Attacks, phases, arenas and tuning are ScriptableObjects. The things that stayed in code are the ones that need to be: the actual motion of a sword rain, the geometry of a beam sweep clipped to the arena bounds.

Attacks as ScriptableObjects

BossAttack is an abstract ScriptableObject exposing one method, IEnumerator Execute(BossController boss). Each concrete attack — SwordRainAttack, BeamSweepAttack, FeatherBarrageAttack, LandAblazeAttack and a dozen more — is an asset in the project, not an instance in a scene. The same attack asset can be dropped into any phase of any fight, and editing its damage or telegraph in the inspector changes it everywhere.

Tuning is applied, not baked

Attacks never read their raw serialized numbers. They go through the boss: damage is multiplied by boss.Tuning.damageScale, telegraph duration by telegraphScale, projectile speed by projectileSpeedScale. So difficulty is one set of multipliers on the fight rather than thirty numbers spread across thirty assets, and making a fight globally slower to telegraph is one field.

Editor tooling

This is the part I would want to talk through in an interview. NewFightWindow scaffolds a new fight — configs, phases, scene, wiring. BossFightBuilder and the two fight-specific builders construct a fight scene from its config assets. ArenaBuilder generates arena geometry from an ArenaLayoutSet. Custom inspectors sit on the config assets.

FightValidator is the one that earns its keep. Data-driven content fails silently when a reference goes missing, so the validator turns "the boss just stands there" into a specific error naming the phase and the field.

Status

A sandbox rather than a game. There is no menu, no progression and no connective tissue between the fights. The player controller has movement, dash, double jump, attack and a ranged projectile, which is enough to fight with.
