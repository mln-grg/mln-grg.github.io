Blacksmith

A Jacksmith-style forge game with a self-imposed rule: no asset files. Every sprite is drawn in code, every sound is synthesised at runtime. The whole game is a program, not a program plus a folder of art.

Type
Personal project
Built with
TypeScript, canvas, Web Audio
Constraint
Zero asset files
Source
On GitHub

The constraint, and why it is interesting

"No assets" sounds like a gimmick and works like a design tool. If a sword sprite is a PNG, changing it is an art task. If it is a function of blade length, taper, guard shape and metal colour, then the game can generate a sword the player designed, and the visual system and the gameplay system are the same system.

The same applies to audio. A hammer strike synthesised at runtime can carry the weight of the blow, the metal it hit and how hot it was — parameters the simulation already has — rather than picking one of three recorded clips.

What I got out of it

  • Procedural drawing forces you to understand the shape. You cannot fake an anvil you have not decomposed into primitives. It is the same muscle as writing a shader: describe it, don't paint it.
  • Runtime audio synthesis is 3D-math practice wearing a hat. Envelopes, oscillators and filters are the same kind of continuous-parameter thinking as interpolation and easing in gameplay code.
  • Small enough to finish. I have prototypes going back to 2020. The ones I learned most from are the ones I closed out, and a hard constraint is a reliable way to keep scope from expanding.
