Benji-2D

A 2D game engine written from scratch in C++ with SDL2, in 2022. I built it to see what an engine does between a key press and a changed pixel.

Entities and signatures

An entity is an integer id. What it is comes from the components attached to it. Each entity carries a std::bitset<32> recording which component types it has, and each system declares the signature it requires. Matching an entity to a system is a bitwise AND — no virtual call, no dynamic cast.

Component type ids come from a templated static counter, so an id is resolved once per type rather than looked up per entity.

Packed component pools

Components live in Pool<T>, a contiguous std::vector<T> kept densely packed. Two maps, entityIdToIndex and indexToEntityId, translate between the sparse entity id space and the packed array.

Removal is the part worth explaining. Instead of leaving a hole, the last element is swapped into the removed slot and both maps are patched. Iteration never has to test for gaps, so systems walk a solid run of memory.

Systems

Thirteen systems, each doing one job: movement integration, sprite rendering with z-sort and culling, sprite animation, AABB collision, damage resolution, keyboard control, projectile emission and lifetime, camera follow clamped to the map, and four debug and overlay renderers including a Dear ImGui panel for inspecting and spawning entities.

Event bus

Systems do not call each other. CollisionSystem publishes a CollisionEvent and DamageSystem handles it, with neither holding a reference to the other. The bus keeps a std::type_index keyed map of subscriber lists, and each subscription binds a member function pointer plus its owning instance, so handlers stay ordinary methods rather than free functions or lambdas.

Entities can also be tagged individually ("player") or grouped ("enemies", "projectiles"). That is how gameplay code finds entities without storing raw pointers into pools that reshuffle on removal.

Limitations I know about

  • Pools grow by doubling and never shrink, and Clear() frees the data while leaving the maps to be reset separately. That lifetime should have a single owner.
  • Systems store std::vector<Entity> by value. Sorting entity ids and storing index ranges would keep iteration closer to the cache behaviour the pools were built for.
  • Collision is a full pairwise sweep. A uniform grid or quadtree is the obvious next step, and it is the reason I paid attention to spatial partitioning later.
  • sol2 and Lua are vendored and linked but never wired into gameplay. The repo description used to claim Lua scripting; it does not any more.
